# 040 · Bulk import of unclaimed organizations from a CSV

**Date:** 2026-11-24
**Status:** Accepted
**Context:** The user is using a research agent to find mutual aid organizations area by area and wanted the results (a CSV, starting with 29 Bay Area groups) added to the database as unclaimed organizations, plus a repeatable way to prepare those files.
**Decision:** A super-user page, `/admin/import`. It takes a CSV, **checks every row first and adds nothing**: the same schema as the create form, plus the place ID against its label, repeats within the file, handles already taken, and organizations already listed with the **same name or website**. The reviewer reads every row, including the research columns (`verification`, `notes`, `sources`), which are shown but never stored. Then **Add N organizations** checks the same text again on fresh data and creates each ready row with `createUnclaimedOrganization`: one transaction each, each with its own `adminLog` entry under the super user. It clears the directory cache. Rows with problems are skipped, never guessed at. The file format and research rules live in a project skill, `.claude/skills/prepare-organizations-csv/`, with a helper that looks up place IDs in the app's own data. The user chose to import all 29 rows, including large staffed nonprofits (food banks, GLIDE) and one row marked "needs verification" (People's Breakfast Oakland).
**Alternatives:** A one-off Node script with the Admin SDK (faster to build, but it would copy the document shape, need production credentials, skip the cache clearing, and be harder to repeat); raw inserts with the Firebase CLI (it can't write Firestore documents, and would skip validation and the log); importing only the volunteer-run mutual aid groups (the user chose all of them, since unclaimed pages exist to help neighbors find help).
**Consequences:** Imported pages say "Unclaimed" and that details may be out of date, but research mistakes are still public. The skill tells researchers to leave a cell blank rather than guess, and the reviewer should read the notes before adding. Duplicate detection is exact (name or website), so "SF Food Not Bombs" and "San Francisco Food Not Bombs" both get in. Up to 200 rows per file. Docs updated: features/18, AGENTS.md.
