# 041 · Import review: explained problems, profile previews, edit and remove

**Date:** 2026-11-24
**Status:** Accepted
**Context:** After trying `/admin/import` (decision #40), the user wanted clearer errors with more insight, to see each organization's details using the organization profile component, to edit and remove rows, and an obvious "add all" button. They had thought **Check file** uploaded the organizations.
**Decision:** The page became a review. **Review file** says it adds nothing. Each row is a card: each problem names the column, says what's wrong, shows the offending value and how to fix it, and duplicates link to the organization they match. **Show profile** opens the real `OrganizationProfile`, which gained a `headingLevel` prop so it can sit inside the list. **Edit** opens the create form in a dialog, filled in from the row (the user chose this over editing raw CSV cells), and **Remove** has Undo. The add button is above and below the list with the counts, and it asks for confirmation. Edits live in the page; **Download CSV** exports the reviewed rows (the user chose this over a browser draft). The browser now parses the file and sends rows; the server checks rows, the database only for edited rows, and everything again before adding.
**Alternatives:** Editing raw cell values (quicker, but no city search and easy to get wrong); saving a draft in local storage (survives a refresh, but leaves research data on the device); a bar stuck to the bottom of the screen (it can cover the focused control, which WCAG 2.2's focus-not-obscured rule forbids); re-checking every row against the database after each edit (simpler, but up to 800 reads per edit at 200 rows).
**Consequences:** Closing the tab loses unsaved review work, so the page and docs say to download first. Docs updated: features/18, the prepare-organizations-csv skill.
