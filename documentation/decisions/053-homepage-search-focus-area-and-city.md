# 053 · Homepage search: "Connect with organizations", a city and focus-area pills

**Date:** 2026-11-26
**Status:** Accepted
**Context:** The homepage banner had **Browse organizations** (to `/find` on the visitor's starting city, [052](052-find-always-has-a-city-profile-or-default.md)) and a second button: Create account, or **Go to your dashboard** when signed in. The user wanted visitors to be able to narrow the search before they land on `/find`, and the dashboard button gone, since the header already links there.
**Decision:**

- The search (`HeroSearch`) sits at the **bottom of the banner** in a full-width translucent band (black at 40% with a light blur, dark theme inside so it reads on any part of the photo; at least 1/6 of the screen tall). In one line, in this order (the user's call): **Connect with organizations**, the **City** picker (the same `LocationField` as everywhere else), then **Focus area** pills (`FocusAreaPills`), **two rows high**, filling each column top to bottom so the most common are on the left. The button and city line up with the header's edges; only the pills may run on, past the header's right edge to the screen edge, and scroll sideways if they're longer than that. On phones the pills go on their own line under the button and city.
- Tags are the existing **focus areas**, not a new tag system, so `/find` already filters by them and nothing changes in the data. The homepage offers only the **broadest, most common** ones: the first 8 of `/find`'s order (`HOME_FOCUS_AREAS`), 4 shown and "+ 4 more" for the rest (`HOME_FOCUS_AREAS_SHOWN`); the others are on `/find`. **One** at a time (the user's call): clicking a pill picks it, another switches, the chosen one again clears it. Searching after clearing opens `/find` with no focus area, even after going back from a search that had one.
- The city box starts on the visitor's starting city (`startingCity`): the profile's city, otherwise **San Francisco, California** (`DEFAULT_PLACE`), the same city plain `/find` starts on ([052](052-find-always-has-a-city-profile-or-default.md)). It's never empty, so people can see where the search will look before they press the button.
- No second button for anyone: "Go to your dashboard" repeated the header link, and the user chose to drop Create account here too. Sign-up stays in the header and the "Ready to organize?" band.
- `homeSearchHref` (`src/lib/organizations/directory.ts`, tested) builds the link. Without JavaScript the form is a plain GET to `/find`, which redirects to the city's path.

**Revised 2026-11-27** (same branch, before merging): the first version put a solid white panel in the middle of the banner, stacked, with a type-ahead **tag box** (`FocusAreaField`, cmdk's fuzzy match) listing every focus area. The user wanted the pills people already know from `/find`, in one line along the bottom of the banner, and the city box to start on San Francisco when signed out instead of empty ("Search location").

**Alternatives:** a type-ahead tag box over every focus area (the first version; finds typos, but hides the choices behind a click); a new tag list (finer-grained, but every group would need tags and `/find` and the data model would change); several tags (the user preferred one); keeping Create account beside the button for signed-out visitors (recommended, but declined: it's in the header and the closing band).
**Consequences:** Signed-out visitors no longer see a sign-up button above the fold except in the header. Narrower focus areas (legal, faith, labor…) can't be picked from the homepage; people add them on `/find`. The button comes before the fields in the tab order, as the user ordered it, so keyboard users reach it before choosing a city or tag.
